## 简介

IAVC-VDSS 是论文 *Incrementally Aggregatable Vector Commitments and Applications to Verifiable Decentralized Storage*（ASIACRYPT 2020 / eprint 2020/149，§5.2 + §8.2）方案的一个完整工程实现。

核心是一条贯穿全系统的设计决定：**每份文件各有一条独立向量**，各有自己的常数大小摘要 δ = (U, C, n)；跨文件验证时在「合并位置集」上重算一份证据。由此获得三个能力：常量摘要、常量证据与一证据跨多文件 —— 而且**新建 / 改动一份文件完全不触碰别人那份的摘要**。

> ★ **素数不再来自「全局素数表」**（2026-10 改造）。第 `i` 块的素数改按**块身份**派生：
> `e_i = H(owner‖file_key‖i)`，见 `svc/primegen_identity.py`。论文 §5.2 只要求 `e_i`
> **互不相同**，原文就写明「even just a bijective mapping (which is inherently collision
> resistant) would be enough」—— 要的是一一对应，不是「按顺序对应」。128 位素数在 8192 块上
> 的碰撞概率约 `10⁻³¹`，而派生时**默认开启互异性检查**（一旦碰撞，`shamir_trick` 会在
> `gcd ≠ 1` 时**静默**算错，那种 bug 靠读代码几乎定位不到）。
> 由此三件事一起消失：**全局位置分配器**（不再需要一本登记表）、**`n_max` 天花板**
> （不再有「全系统最多存多少块」的限制）、**删除留下的空洞**（删了再传同一块，拿到的还是同一个素数）。
>
> 边界：`offset` **没有消失**，但它降到「**存储槽位号**」（密文放哪个槽位），
> 已不参与任何验证；详见 [`docs/开发与验收记录.md`](docs/开发与验收记录.md) 第十四章。
在这些密码学能力之上，系统补齐了分布式存储节点、加密存储、密钥封装、完整性验证、存储证明（PoR）、审计回放与 Web 界面，构成一个可演示、可复现的完整系统。

## 功能特性

- **可验证存储**：摘要与证据大小均为常数（上界 256 字节），与文件大小、块数无关。
- **跨文件聚合**：一份证据可同时覆盖多个文件、多个用户。★ 新架构下**每份文件一条独立向量**，所以跨文件时要在“合并位置集”上**重算**一份证据与合并承诺 —— 与设计 B 的“天然合成”不同（那时全系统共用一条向量）。代价是秒级，换来的是「新建 / 改动一份文件**完全不触碰**别人那份的摘要」。合并时各文件的素数由**各自那份坐标**给出（新文件按块身份派生、旧文件查素数表），所以两种坐标可以长期共存。
- **加密存储**：SM4-CTR 分段加密（每段独立密钥与 IV）+ SM3 分量（32 字节摘要 —— 它就是被承诺的那个「指纹」）。
- **密钥封装**：块密钥用所有者的 SM2 公钥封装（ECIES），用户私钥用登录口令封装（PBKDF2-HMAC-SM3），全库不留明文密钥。
- **验证不受限 / 解密受限**：任何人都能验证完整性（公开可验证），只有所有者能解密（密码学强制，管理员也不行）。
- **分布式存储节点**：N 台独立进程 + 各自 SQLite；块按**打乱顺序后的轮转**分片（主/副本的搭配每次上传都不同），每块默认 2 份副本。
- **增量更新**：改块 / 追加 / 截断 / **删整份文件** / **把某一块清零**（换成等长全 0：它走的是改块而不是删除 —— 块仍在、下标不变、总块数不变，完整性照样验证通过，只有所有者解密时看得到那串 0）。前几种代价只与改动量成正比，**别人那份文件一个字节都不动**（每份文件一条独立向量）；删整份文件只影响它自己 —— 它占的位置段会空出来，但段**永不回收**，原来压在它后面的文件照样待在自己的位置上。
- **存储证明（PoR）**：随机挑战，常数大小的证明确认各节点仍持有数据。
- **故障演练**：把若干台节点模拟成「掉线」或「永久损毁」（地震 / 海啸），并算出**影响面** —— 哪些块的主副本出事但副本救得回来（照常可用）、哪些块的**每一份副本都在故障机器上**（现实中会永久丢失）。它只让指定节点不可达，**密码学与分片一个字都不改**，所以看到的失败是真代码在「这台机器没了」时的真实行为：验证 / 聚合 / 取块会报「取不到密文」，改块 / 追加 / 截断会被拦下。★ **它一个字节都不会删** —— 两种模式都只改两张名单，点「恢复」立刻全部复原；「会永久丢失哪几块」是**算出来的预判**，不是真删。
- **Web 界面**：Vue 3 + Vite + Element Plus，**18 条路由**（16 个功能页面：登录、总览、文件与块、文件详情、证据池、完整性验证（多指标筛选 + 把块收进**集合**一次验完）、设备（存储节点）与节点详情/新增、用户管理与详情、审计、性能、个人中心、界面偏好；另有 403 / 404 两张兜底页）。
- **审计回放**：只记元数据，被拒也留痕；可按对象 / 操作者精确匹配回放。

## 快速开始

### Windows 一键启动（推荐）

项目根目录下双击即可：

| 脚本 | 作用 |
|---|---|
| `一键启动.cmd` | 按部署配置的台数（默认 4 台）与端口起存储节点 + 后端 + 前端，并打开浏览器。**不提问** |
| `重置并启动.cmd` | 清空演示数据、只重建账号后启动，**并把服务器台数与端口一起复位成默认值（4 台 / 8000 / 5173 / 9101 起）** |
| `停止.cmd` | 停掉全部存储节点、后端、前端（端口取自 `nodes/deploy.json`；另外还会扫默认那一段，收拾以前留下的残留） |

> 台数与端口不再由启动脚本写死或提问：它们存在 `nodes/deploy.json`，改它们的地方是**管理员界面**
> 「设备（存储节点）」页顶部那两张卡片（服务器台数 / 端口） —— 改完点「立刻重启」。
> 见下面「改服务器台数」与「改端口」。

演示账号（口令统一 `vds12345`）：

| 用户名 | 身份 |
|---|---|
| `admin` | 管理员（可看审计、管用户，但解不开别人的文件） |
| `zhangsan` | 张三，4 份病历的所有者 |
| `wangwu` | 王五，只有一份会议纪要 |

### 手工启动

```powershell
# 一键起全套（保留已有数据）
python scripts/start_all.py
python scripts/start_all.py --nodes 2   # 只起 2 台节点
python scripts/start_all.py --reset     # 清空重建再起
python scripts/start_all.py --stop      # 全部停掉
```

> 完整的单进程 / 跨进程两种模式、环境变量、依赖安装与接口清单，见 [`docs/复现指南.md`](docs/复现指南.md)。

### 改服务器台数（管理员）

**在界面上改，重启后生效；数据一行都不动。**

1. 管理员登录 → 「设备（存储节点）」页顶部「服务器台数」卡片；
2. 填台数 → 「保存」。**改小时会先算一遍**（要摘掉哪几台、要搬多少块、有没有搬不动的），
   把后果摆在按钮旁边；确认后**趁被摘掉的机器还活着**把已经承诺过的文件块搬到留下的机器上
   —— 块内容、全局下标与承诺一个字都不变，**不会丢块**；
3. 点「立刻重启」（或那个按钮旁边就有的同一个入口）—— 它在一个独立窗口里停掉
   节点 / 后端 / 前端，再按新台数起一遍。**完成后浏览器会自动回到登录页**
   （后端重启会换一把 JWT 签名密钥，旧令牌必然失效）—— 不用再去按一次
   `一键启动.cmd`。原来那个控制台窗口会**自己让位并关掉**，新的控制台就是重启器那个窗口。

两条容易误解的规则：

- **增台不搬旧块**（4 → 6）：旧块留在原处不动，只有之后新写入的块才会摊到新机器上；
  但**追加**到一份已有文件时，新块仍跟着那份文件原来那几台走 —— 追加不是重建布局。
- **缩容要搬块**，因为被删掉的机器上的副本会随之消失。这也是为什么搬迁发生在**保存**那一步
  （那时源机器还活着），而不是真的拖到重启之后。

台数记在 `nodes/deploy.json`（**不在库里**：重置演示数据时不应把它顺手删掉）。
命令行也能显式指定，并会写回这份配置：`python scripts/start_all.py --nodes 6`。

### 改端口（管理员）

**同上：在界面上改，重启后生效；数据一行都不动。**

端口与台数存在**同一个文件**（`nodes/deploy.json` 的 `ports`），因为它们是同一件事的两面；
启动脚本不写死任何端口，界面入口是「设备（存储节点）」页顶部那张「端口」卡片。

1. 「端口」卡片里改：后端、前端、以及**每一台存储节点各自的**端口（默认 8000 / 5173 / 9101、9102…）；
2. 点「检查占用」：每个端口现在空不空、有没有被别的程序占着 —— 只探测，**不读取也不显示**
   占用者的进程信息；被占着**不拦保存**（可以先存下来、过后再腾端口）；
3. 「保存」→ 弹一句问要不要现在重启；重启之后前端可能换了地址（重启器会在新地址自动开一个）。

两条硬规则：

- **两样东西填同一个端口（两个节点之间、或节点与前后端之间）会被拦下来**（409）——
  那不是风险，是确定失败：重启时后起的那个一定绑不上；
- **改了端口不用搬块**：端口只影响"怎么找到那台机器"，与"第几台存了哪些块"无关，
  块、下标、承诺、证据全部原样。

命令行也能显式指定（与 `--nodes` 不同，它**不**写回配置）：

```powershell
python scripts/run_nodes.py --urls "node-1=http://127.0.0.1:9201,node-2=http://127.0.0.1:19301"
```

## 项目结构

```
IAVC-VDSS/
├─ svc/                 论文 §5.2 的 SVC（算法核，零依赖）
├─ vds/                 论文 §8.2 的 VDS（算法核，零依赖）
├─ core/
│  ├─ store.py          VectorStore —— 上传/加密/承诺/分发/检索/聚合/验证/解密
│  ├─ keywrap.py        密钥封装层（取代 ABE）：公钥封块密钥 + 口令封私钥
│  ├─ sm2.py            SM2 曲线原语（手写）
│  ├─ crypto.py         SM4-CTR 分段加密 + SM3 分量（承诺的对象）
│  ├─ node_state.py     节点本地状态机
│  ├─ registry.py       全局块索引登记表
│  ├─ session.py        全局会话 + CRS
│  └─ transport.py      节点协议 + LocalTransport + WriteError
├─ node_service/        存储节点服务（一个进程 + 一个 SQLite）
├─ backend/             FastAPI + SQLite + JWT；验证不受限 / 解密受限
│  └─ routers/          auth / admin / files / verify / system
├─ scripts/             seed（建账号）/ run_nodes / start_all（一键起停）/ bench_*（性能基准，实测数字的来源）
├─ frontend/            Vue 3 + Vite + Element Plus（18 条路由）
├─ demo.py              端到端演示 + 性能指标
└─ docs/                方案设计 + 复现指南
```
