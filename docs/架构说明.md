# 架构说明

本文描述系统的分层、模块职责、数据模型、关键数据流，以及**改代码时不允许破坏的不变式**。
面向开发与维护人员；操作步骤见 [复现指南](复现指南.md)，验收方法见 [开发与验收记录](开发与验收记录.md)。

---

## 一、分层与依赖方向

```
        frontend/  (Vue 3 + Vite，浏览器侧完成加密/解密/验证)
             │  HTTP + JSON
        backend/   (FastAPI + SQLAlchemy + SQLite)
             │
          core/    (系统层：会话、承诺向量存储、节点状态机、传输层)
             │
          vds/     (VDS 应用层：编码、摘要、存储节点、客户端节点、更新、PoR)
             │
          svc/     (算法内核：向量承诺、隐藏阶群、素数映射。**零第三方依赖**)
             │
        node_service/  (独立进程的存储节点 HTTP 服务，复用 core + vds)
```

依赖方向**单向**：`svc` 不认识 `vds`，`vds` 不认识 `core`，算法核不 import 系统层。
`cryptography`（SM3 / SM4）只被 `core` 使用；`svc` 与 `vds` 只依赖标准库。
这条边界使得"单独把算法核拿去跑"是可行的（`verify_identity_primegen.py` 就是这样用的）。

## 二、模块职责

### 2.1 `svc/` —— 算法内核

| 模块 | 职责 |
|---|---|
| `scheme.py` | 向量承诺主体：`commit` / `open` / `verify` / `agg` / `disagg`（论文 §5.2） |
| `fastopen.py` | 带预处理的提交与打开：`VC.PPCom` / `VC.FastOpen`（论文 §4.2） |
| `groups.py` | 隐藏阶群生成。正确性要求：**丢弃 φ(N)**，无人知道群阶 |
| `mathbase.py` | 数学底座（模幂、连乘、求逆等） |
| `primegen.py` | 下标 → 素数的映射（老坐标：素数表第 i 项） |
| `primegen_identity.py` | 按**块身份** `(owner, file_key, block_idx)` 派生素数（新坐标） |
| `rng.py` | 确定性随机源；不给种子时取真随机 |
| `types.py` | 方案用到的数据结构 |

### 2.2 `vds/` —— VDS 应用层

| 模块 | 职责 |
|---|---|
| `encoding.py` | 文件 ↔ 分块 |
| `digest.py` | 摘要与本地视图（`check_local_view`） |
| `storage_node.py` | 存储节点算法族（论文 §7 `StrgNode`） |
| `client_node.py` | 客户端节点算法族（论文 §7 `ClntNode`） |
| `updates.py` | 文件更新：`PushUpdate` / `ApplyUpdate`（论文 §8.2） |
| `pos.py` | 存储证明（Proof of Retrievability，附录 D.1） |
| `vds.py` | 把以上模块串成可执行流水线 |

### 2.3 `core/` —— 系统层

| 模块 | 职责 |
|---|---|
| `session.py` | 公开参数会话：CRS 的生成、落盘缓存、新旧两套素数坐标并存 |
| `store.py` | `VectorStore`：**协调者**。持有文件登记、承诺向量、证据、删除与故障处理 |
| `registry.py` | 位置段登记表（一文件一条向量；段永不回收） |
| `crypto.py` | 明文 → 可承诺的向量（SM3 分量、SM4 加密） |
| `keywrap.py` | 块密钥的 SM2 ECIES 封装、用户私钥的口令封装（PBKDF2-SM3 + SM4） |
| `sm2.py` | SM2 曲线点运算（ECDH 底座） |
| `node_state.py` | 单个存储节点的本地状态机 |
| `transport.py` | 节点传输层：进程内与 HTTP 两种实现，对上接口一致 |
| `faults.py` | 故障演练：把节点模拟成"掉线"或"永久损毁" |
| `timing.py` | 阶段秒表，给前端报每一步的真实毫秒数 |

### 2.4 `backend/` —— HTTP 服务

| 模块 | 职责 |
|---|---|
| `main.py` | 应用装配：路由注册、启动时加载 CRS 与存储 |
| `config.py` | `Settings`：端口、块大小阶梯、`n_max`、副本数、超时、密钥等 |
| `manager.py` | `StoreManager`：`VectorStore` 与 SQLite 的缝合层，所有业务事务在此提交 |
| `models.py` | SQLAlchemy 表定义（12 张表，见第三节） |
| `schemas.py` | 请求体模型与长度上界（`MAX_INDICES` 等） |
| `security.py` | 口令哈希（bcrypt）与 JWT 签发/校验 |
| `deps.py` | 依赖注入：配置、管理器、当前用户、管理员校验 |
| `errors.py` | 统一错误：一句话 + 稳定错误码（前端 `data/errors.js` 与之一一对应） |
| `advisor.py` | 切块顾问：按文件大小与实测系数给出切法建议 |
| `metrics.py` | 运行性能采集（供总览页「运行性能」面板） |

### 2.5 `node_service/` —— 存储节点进程

`server.py` 暴露节点 HTTP 接口；`persist.py` 负责节点本地 SQLite；`client.py` 是协调者侧的调用封装。
节点只保存"槽位 → 密文 + 分量 + 封装密钥"，**不持有任何用户私钥**。

### 2.6 `frontend/` —— 浏览器端

- `src/utils/crypto/`：纯 JS 实现的 SM2 / SM3 / SM4 / PBKDF2 / 密钥封装，与 Python 侧逐字节对齐
  （向量由 `scripts/gen_crypto_vectors.py` 生成，`frontend/tests/crypto.test.js` 钉住）。
- `src/stores/`：Pinia 状态（`basket` 证据集合、`deltaAnchors` 本地 δ 锚、`crypto` 私钥解锁态）。
- `src/views/`：总览、文件（上传/列表/详情/更新）、可验证查询、增量聚合与分解、管理员工作台（用户/存储节点/审计/初始化与系统自检）。
- `src/data/`：`copy.js`（界面文案，纯函数）、`errors.js`（错误码表）、`measured.js`（方案常量与实测数字）。

## 三、数据模型

主库 `vds.db`（SQLite，WAL 模式）共 12 张表：

| 表 | 内容 |
|---|---|
| `crs` | 公开参数 `(N, g, l, n_max)`，**全库只有一行** |
| `meta` | 键值元数据（建库标记等） |
| `file_deltas` | 每份文件的承诺向量 `(U, C, n, offset, fp)` |
| `users` | 账号、口令哈希、角色、用户公钥与口令封装的私钥 |
| `files` | 文件登记（所有者、标识、块数、字节数、版本、分块大小） |
| `blocks` | 每块的全局位置、分量、密文引用、IV |
| `node_blobs` | 槽位 → 节点上的密文与封装密钥 |
| `node_state` | 节点在线/损毁状态 |
| `node_registry` | 协调者视角的段登记（哪个 offset 属于哪个文件） |
| `audit_log` | 审计流水（动作、对象、结果、备注） |
| `revoked_tokens` | 已注销 JWT |
| `replay_blocks` | 「回滚演示」保存的旧版本密文（演示服务器不可信用） |

节点自己的库是 `nodes/node-<i>/node.db`，只存该节点负责的槽位数据，结构独立。

## 四、关键数据流

### 4.1 上传（`POST /api/files`）

1. 按 `auto_segment_bytes` 或用户指定大小切块；
2. 每块：SM4 加密，SM3 计算公开分量 $v_i$；
3. 每块生成随机块密钥，用**用户 SM2 公钥**做 ECIES 封装；
4. 分配存储槽位（`offset` 只用于定位，不参与验证）；
5. 在**该文件自己的向量**上计算承诺 $C_f$ 与 $\delta_f=(U,C)$；
6. 按副本数把密文推到各存储节点；任何一步失败则本次上传作废。

### 4.2 可验证查询（`POST /api/query`）

1. 协调者按请求的全局下标定位到 `(文件, 块号)`；
2. 向持有该块的节点收取检索凭证；
3. 客户端在本地合成证据 $\pi_I=(S_I,\Lambda_I)$，并验证；
4. 响应里附带每块的当前持有节点与分量，界面可逐块展开。

**证据大小与块数、文件大小无关**：$\pi_I$ 恒为两个群元素（上界 256 字节）。

### 4.3 解密（`POST /api/files/{id}/decrypt`）

1. 服务端校验**所有权**（仅所有者可解密；管理员也不行）；
2. 返回密文、IV 与封装后的块密钥；
3. 浏览器用已解锁的私钥解封块密钥 → SM4 解密 → SM3 校验分量；
4. 校验失败即视为"服务器交回的不是这一版"，界面提示并可重试。

### 4.4 聚合与分解

- `POST /api/evidence/agg`：两份证据合成一份（$\pi_I\otimes\pi_J=\pi_{I\cup J}$），**不向节点取任何数据**；
- `POST /api/evidence/disagg`：从 $\pi_I$ 拆出 $\pi_K$（要求 $K\subseteq I$），可一步直达任意子集。

跨文件合并时，各文件的素数由**各自那份坐标**给出（新文件按块身份派生、老文件查素数表），两种坐标可以长期共存。

## 五、关键设计决定

1. **一文件一向量**。每份文件在自己的向量上承诺，`offset` 仅是存储槽位。
   由此：新建/改动一份文件**完全不触碰**别人那份的摘要；代价是跨文件合并要在合并集上重算一份证据。
2. **素数按块身份派生**。块的身份是 `(owner, file_key, block_idx)`，与"全系统第几个块"无关。
   由此：不存在"全系统位置预算"上限，删除后重传同一块拿到的仍是同一个素数（无空洞）。
3. **证据常数大小**。无论覆盖 1 块还是上万块，证据都是 2 个群元素。
4. **服务端不可信**。验证结论必须由浏览器本地计算；本地 δ 锚（TOFU）一旦建立，服务端无法替换。
5. **验证不受限、解密受限**。任何登录用户可验证任何文件的块；解密只对所有者开放。

## 六、部署形态

| 形态 | 说明 |
|---|---|
| 单进程 | 节点在协调者进程内运行（`transport` 的本地实现），便于离线验收脚本 |
| 跨进程 | 4 台（可配 1–N）独立 `node_service` 进程 + 协调者 + 前端；端口与台数写在 `nodes/deploy.json` |

两种形态共用同一套 `core` / `vds` 代码，差别只在 `transport` 的实现。

---

## 七、不变式（改代码时不许破坏）

1. **摘要隔离**：对文件 $f$ 的写操作不得改变其他文件的 $\delta$。
2. **证据常数**：$\pi_I$ 的大小与 $|I|$、文件块数无关。
3. **`offset` 不参与验证**：它只决定密文存在哪个槽位；把它写进验证路径即破坏第 1 条。
4. **群阶不可知**：任何代码路径都不得导出 $\varphi(N)$；`svc/groups.py` 生成后即丢弃。
5. **验证在本地**：前端不得用服务端返回值替代本地计算结果（见 `frontend/tests/delta-anchor.test.js`）。
6. **块身份稳定**：`(owner, file_key, block_idx)` 一旦分配不得变更，否则旧证据全部失效。
7. **步骤名对齐**：前端的步骤 `key` 必须与后端 `with stage("…")` 的埋点名逐字相同
   （由 `scripts/check_stage_names.py` 强制）。
8. **错误码一一对应**：后端 `ApiError` 码表与前端 `data/errors.js` 必须等长且同名
   （由 `scripts/check_error_codes.py` 强制）。
