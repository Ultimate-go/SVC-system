# 文案与注释规范

适用范围：`frontend/src` 下所有界面文字、提示语与代码注释。
（后端的界面可见文案同样遵守第一、三节。）

## 一、文体

1. 一律陈述句。不用感叹号，不用问句，不用"让我们 / 你可以 / 不妨"。
2. 不用比喻与拟人。禁用词举例：搬运工、主人、房东、如实报、墓碑、
   账上有人、宇宙、世界、问一遗、硬收缩、别管。
3. 不写开发叙事。禁用："踩过的坑""上次""我当初""别再删第二次""原实现保留在这里"。
   需要防止的错误改写为规则：**条件 → 结论 → 违反后果**。
4. 不用装饰标记。`★`、`★★`、`❗`、多重箭头链一律删除；强调靠词序，不靠符号。
5. 一个句子表达一件事；超过 40 字的句子拆分。

## 二、术语（统一写法）

| 统一写法 | 含义 | 不再使用 |
|---|---|---|
| 位置 / 全局下标 | 登记表中的位置号（可稀疏） | 坑位、洞、槽位号 |
| 存储槽位 | `offset`：密文在节点上放哪个槽（**不是**密码学坐标） | — |
| 块 / 块号 | 文件内的块序号 | 碎片、分片 |
| 承诺 δ / C | 增量承诺与文件承诺 | 指纹（仅当确指 fp 时可用） |
| 凭证 π | 聚合证据 | 证明（证 ≠ 凭证） |
| 副本 / 持有者 | 份数与所属节点 | 主人、房东 |
| 登记表 | registry | 台账 |
| 合并向量 | 跨文件归约后的向量 | 宇宙、世界 |
| 判据 | 判定条件 | 标准（当"判据"用时） |

算法与协议名保留英文原词：VDS、VerRetrieve、VC.Agg、IdentityPrimeGen、PoS。

## 三、界面文案

1. 顺序：是什么 → 会发生什么 → 用户需要做什么。
2. 危险操作先给后果，再给操作入口。
3. 界面文字里不能出现 Markdown 记号（`**`、反引号）；需要引用名词用「」。
4. 数字带单位：`381.6 ms`、`124 个位置`、`3 份文件`。
5. 人看到的序号从 1 起（第 1 块）；内部下标从 0 起。
   换算只允许出现在 `utils/format.js` 与 `utils/validate.js`。

## 四、注释

1. 只写三类内容：①不变式；②参数取值约束；③违反后果。
2. 不写实现历史。必须保留的结论改写成规则句。
3. 模块头部写明职责与边界（做什么、不做什么）。
4. 引用其它实现时给出符号名（如 `StoreManager.redistribute`），
   不写"上面那个文件""之前那个函数"。
5. 键盘循环动画等动效：注明是否常驻播放，以及 `prefers-reduced-motion` 的处理方式。
