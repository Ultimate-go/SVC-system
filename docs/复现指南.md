# 复现指南

本文只写"怎么把它跑起来、怎么验"；设计原理见 [架构说明](架构说明.md)。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 | 一键启动脚本是 `.cmd`；其余命令在 PowerShell 中执行 |
| Python | ≥ 3.10（开发实测 3.12） | 后端、验收脚本、节点服务 |
| Node.js | 满足 Vite 8 的要求 | 前端构建与单元测试 |
| 磁盘 | ≥ 200 MB | 含 `node_modules` 与素数缓存 |

依赖清单见 `requirements.txt`（后端）与 `frontend/package.json`（前端）。

---

## 二、安装

```powershell
# 后端依赖
python -m pip install -r requirements.txt

# 前端依赖（首次或依赖变更时）
npm --prefix frontend install
```

`svc/` 与 `vds/` 两个算法包**零第三方依赖**，只用标准库；`cryptography` 仅被 `core/` 用于 SM3/SM4。

## 三、启动与停止

### 3.1 一键启动（推荐）

```
双击  一键启动.cmd
```

它会依次：清掉上次残留 → 起 N 台存储节点 → 起后端 → 起前端 → 打开浏览器。

### 3.2 命令行启动

```powershell
python -X utf8 scripts/start_all.py                # 按 nodes/deploy.json 起
python -X utf8 scripts/start_all.py --demo         # 顺带灌 5 份演示文件
python -X utf8 scripts/start_all.py --nodes 3      # 改台数（会写回配置）
python -X utf8 scripts/start_all.py --reset        # 清库重建（账号保留重建），台数复位为 4
python -X utf8 scripts/start_all.py --stop         # 只停，不起
python -X utf8 scripts/start_all.py --no-browser   # 不自动开浏览器
python -X utf8 scripts/start_all.py --warm 10000   # 素数表预计算到 10000 条
python -X utf8 scripts/start_all.py --strict       # 任一进程退出即整体停止
```

| 参数 | 作用 |
|---|---|
| `--reset` | 清空主库与各节点数据（账号保留并重建）；台数复位为 4 |
| `--demo` | 启动后灌 5 份演示文件 |
| `--stop` | 停掉节点 / 后端 / 前端 |
| `--no-browser` | 不自动打开浏览器 |
| `--warm N` | 素数表预热到 N 条（`0` = 跳过，`10000` = 算满） |
| `--strict` | 任一子进程退出就整体停止（默认只报警，便于演示"kill 一台看降级"） |
| `--nodes N` | 存储节点台数（写入 `nodes/deploy.json`） |

### 3.3 停止与重置

```
双击  停止.cmd          # 停掉全部进程
双击  重置并启动.cmd     # 清库 + 节点数据，重建后启动
```

停止脚本按端口清理：`5173`、`8000`、`9101`–`9104`。

## 四、端口与部署配置

| 入口 | 地址 |

## 五、演示账号

口令统一为 `vds12345`：

| 账号 | 角色 | 能力 |
|---|---|---|
| `admin` | 管理员 | 用户管理、存储节点、审计流水、初始化与系统自检；**不能**解密他人文件 |
| `system1` | 普通用户 | 上传自有文件；可验证所有文件；只能解密自己持有的文件 |
| `system2` | 普通用户 | 用于演示"验证不受限、解密受限" |

> 内置账号在**建库时**创建。若库里还是旧的内置账号（`zhangsan` / `wangwu`），
> 直接改名会破坏数据：`owner` 参与块身份派生素数，改了会让旧证据与旧块全部对不上。
> 换新账号的唯一干净做法是整套重建：`重置并启动.cmd`（等价于 `start_all.py --reset`）。

## 六、端到端演示

```powershell
python -X utf8 demo.py
```

在单个 Python 进程内完整走一遍：建会话 → 上传 → 查询/验证 → 改块 → 追加 → 聚合 → 分解 → 删除，
并打印每一步的实测耗时。它不依赖已启动的服务，适合在没有界面的环境里快速自检。

## 七、验收脚本

### 7.1 九份可离线验收（不启服务，逐条打印 PASS/FAIL）

```powershell
python -X utf8 scripts/verify_identity_primegen.py    # 1. 身份派生素数能否跑通全部算法
python -X utf8 scripts/verify_session_identity.py     # 2. 会话层新旧两套坐标并存
python -X utf8 scripts/verify_store_identity.py       # 3. 上传/改块/追加/聚合/截断/删除
python -X utf8 scripts/verify_backend_identity.py     # 4. 真库 + 模拟重启
python -X utf8 scripts/verify_node_wire.py            # 5. 跨进程线格式（真 JSON，不起端口）
python -X utf8 scripts/verify_fault_drill.py          # 6. 节点掉线 / 永久损毁的真实反应
python -X utf8 scripts/verify_incremental_agg.py      # 7. 增量聚合与一步分解
python -X utf8 scripts/verify_segment_ladder.py       # 8. 自动切块阶梯python -X utf8 scripts/verify_write_rollback.py       # 9. 写失败后节点侧撤回 + 落库原子性```

每份脚本退出码为 0 表示全部通过；失败时打印具体断言与期望值。

### 7.2 需要服务在跑的接口层端到端

```powershell
# 先启动（另一个终端）
python -X utf8 scripts/start_all.py

# 再跑
python -X utf8 scripts/_e2e_api.py
```

打真的 8000 端口 + 真的节点进程：登录 → 上传 → 改块 → 追加 → 截断 → 检索 → 批量验证 →
聚合/分解 → 存储证明 → 故障演练（掉线 → 写失败 → 恢复 → 重做）。

### 7.3 四项静态自检（不起服务、不跑数据）

```powershell
python -X utf8 scripts/check_stage_names.py        # 前端步骤 key ↔ 后端 stage 埋点名
python -X utf8 scripts/check_error_codes.py        # 后端错误码 ↔ 前端 errors.js
python -X utf8 scripts/check_node_report_cache.py  # 节点现状缓存与失效时机
python -X utf8 scripts/check_js_wrap.py            # 「JS 封 → Python 解」互通
```

`check_js_wrap.py` 依赖前端测试落盘的文件，先执行：

```powershell
npm --prefix frontend test
```

### 7.4 基准与标定

```powershell
python -X utf8 scripts/bench_batch.py       # 跨文件批量验证到底值不值
python -X utf8 scripts/bench_blocksize.py   # 块大小选多少最划算（本项目实测）
```

### 7.5 其他运维脚本

| 脚本 | 用途 |
|---|---|
| `scripts/seed.py` | 建库并灌演示账号；`--reset` 会清掉所有文件 |
| `scripts/run_nodes.py` | 单独起 4 台节点（前台，Ctrl+C 一起退） |
| `scripts/gen_crypto_vectors.py` | 重新生成前端对齐测试向量 |
| `scripts/restart.py` | 「立刻重启」按钮背后的重启器（由后端调起，一般不手动跑） |

## 十、常见问题

**端口被占用。** 先跑 `停止.cmd`，或 `python scripts/start_all.py --stop`；它按 `deploy.json` 的
`stop_ports` 清理。仍占用时检查是否有别的 Python/Node 进程。

**首次启动慢。** 素数表是惰性生成并落盘缓存的（`.primecache/primes-b257.txt`）。
257 位素数实测 5–7 ms/个，首次算满会花数十秒；之后各进程直接读回。
不希望等就在启动时加 `--warm 0`，让用量驱动生成。

**控制台中文乱码 / 符号报错。** 所有脚本都按 UTF-8 输出。PowerShell 中建议：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python -X utf8 scripts/verify_store_identity.py
```

**日志在哪。** `logs/backend.log`、`logs/frontend.log`、`logs/nodes.log`，由启动脚本创建；
`logs/` 与 `*.log` 均不进仓，可随时删除。

**改了前端但界面没变。** 确认是 `npm run dev`（即时编译）而不是旧的 `dist`。
`frontend/dist` 只是打包产物，过期后会产生"看到旧界面"的假象。

**重置后解密失败。** 重置会生成新的 CRS，浏览器里保存的本地 δ 锚因此失效。
界面会提示"与本地记录不一致"，确认后重新见证一次即可恢复；这不是数据损坏。
