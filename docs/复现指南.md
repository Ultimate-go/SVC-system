## 2. Windows 一键启动（推荐）

项目根目录下三个双击即用的脚本：

| 脚本 | 作用 |
|---|---|
| `一键启动.cmd` | 按部署配置的台数（默认 4 台）与端口起存储节点 + 后端 + 前端，并打开浏览器。已在跑的不会再起一个，点两下也安全。**不提问台数** |
| `重置并启动.cmd` | 先清空演示数据（`vds.db` + 各节点库）、只重建账号，再起。不灌演示文件。**并把台数与端口一起复位成默认值**（4 台 / 8000 / 5173 / 9101 起），并把这些旧端口累加进 `stop_ports` 以便还能停干净 |
| `停止.cmd` | 停掉全部存储节点、后端、前端（端口取自 `nodes/deploy.json` 与它记的 `stop_ports`，另外还扫默认那一段）。只收**本系统的**进程（按命令行判），不会误杀别人占着同一个端口的程序 |

脚本等价于：

```powershell
python scripts/start_all.py            # 起（保留已有数据；台数与端口读 nodes/deploy.json）
python scripts/start_all.py --nodes 2  # 只起 2 台节点，并把 2 写回部署配置
python scripts/start_all.py --reset    # 清空重建再起（台数与端口一并复位成默认值）
python scripts/start_all.py --stop     # 全部停掉
python scripts/start_all.py --no-browser
```

日志在 `logs/backend.log` 与 `logs/frontend.log`；起不来时会自动把日志尾巴打出来。

> ⚠️ **为什么要有这个脚本**：跨进程模式要求 `VDS_NODE_URLS` 与 `VDS_NODE_TOKEN` 与后端写在同一个终端里。漏了的话后端会静默变成单进程模式，然后被启动闸以「存储节点与协调者不同步」拒绝启动 —— 那个报错看起来像数据坏了，其实只是环境变量没传进去。（真发生了也不会损坏数据：启动闸在任何写入之前就拦下了。）

### 改服务器台数（管理员）

**在界面上改，重启后生效；数据一行都不动。** 台数存在 `nodes/deploy.json`，
启动脚本不再提问台数（这也是为什么 `--nodes` 不是必须的）。

1. 管理员登录 → 「设备（存储节点）」页顶部「服务器台数」卡片；
2. 填台数 → 「保存」。**改小时会先算一遍**（`GET /api/admin/deploy/plan`，只算不动）——
   要摘掉哪几台、要搬多少块、有没有搬不动的，都摆在按钮旁边；确认后**趁被摘掉的机器
   还活着**把已承诺过的文件块搬到留下的机器上（块内容、全局下标与承诺一个字都不变）；
3. 点「立刻重启」（`POST /api/admin/deploy/restart`）：它在**一个独立窗口**里停掉
   节点 / 后端 / 前端，再按新台数起一遍（那个窗口就是重启后的控制台）。
   **完成后浏览器会自动回到登录页** —— 后端每次启动都会随机生成一把 JWT 签名密钥，
   所以旧令牌必然失效；界面在轮询到后端答话（哪怕回的是 401）之后会清掉本地会话
   并跳到登录页，不用再去按一次 `一键启动.cmd`。
   给上一次那个控制台窗口留了一个**交接标记**（`logs/restart.pending`）：
   它看到标记就会主动让位（退出码 0，窗口自己关掉），而不会再去扫端口收尾 ——
   那一下会把刚起的新节点一并收走。

两条容易误解的规则：

- **增台不搬旧块**（例 4 → 6）：旧块留在原处不动，只有之后新写入的块才会摊到新机器上
  （**追加**到一份已有文件时，新块仍跟着那份文件原来那几台走 —— 追加不是重建布局）；
- **缩容要搬块**：被删掉的机器上的副本会随之消失，所以搬迁发生在**保存**那一步（那时
  源机器还活着），而不是拖到重启之后。搬完会把「服务器数量减少，文件块已重新分配」
  显示出来，重启完成后它仍在。

> 缩容保存之后、重启之前，被摘掉的那几台**还在跑**，而且手里还留着旧副本：
> VDS 只能删向量**末尾**，所以这几份多出来的副本结构上删不掉。它们已不参与分发与检索
> （账目以留下的那几台为准），自检会把这件事作为 `notes`（**提示**，不是错误）报出来，
> 重启之后自检就是干净的。

### 改端口（管理员）

**与台数同一个文件、同一套模型：在界面上改，重启后生效；数据一行都不动。**
端口存在 `nodes/deploy.json` 的 `ports`（每台节点各自一个，按节点 id 记） ——
为什么要与台数放在一起、以及为什么还要记一份 `stop_ports`（累加的历史端口），见 `backend/config.py`
里那段注释（一句话：停进程是按端口扫的，没记住旧的那一套就停不掉它）。

1. 「设备（存储节点）」页的「端口」卡片：后端 / 前端 / 每一台节点各自一个输入框；
   「填默认值」一键回到 8000 / 5173 / 9101,9102…；
2. 「检查占用」（`POST /api/admin/ports/plan`，**只探不写**）：判据是真的去 `bind` 一下
   （带 `SO_REUSEADDR` 在 Windows 上能“抢占”别人的监听端口，会把占用误报成空闲）。
   它只看端口：**不读取也不显示**占用者的进程名/PID；
3. 「保存」（`PUT /api/admin/ports`）→ 问一句要不要现在重启。重启之后如果前端换了地址，
   当前页面会失效 —— 重启器会自动在新地址开一个，卡片上也会把新地址写清楚。

两条分寸（这是这个功能最关键的地方）：

- **自己撞自己 → 拦**：两个节点之间、或节点与前后端之间填同一个端口，重启时后起的
  那个一定绑不上，所以后端返回 **409** 并把这几种情况一句句列出来（界面本地也会先拦一次）；
- **被别的程序占着 → 只提示**：那是机器的状态，不是配置的错，所以照样保存 ——
  你可以先把它存下来、过后再腾端口。重启时那一样起不来，启动器会把端口号打出来告诉你。

停止与重启时**只收本系统的进程**（按命令行认），“端口可配”这个能力才不会变成
“一键误杀别人的程序”。

| 用户名 | 身份 |

| `zhangsan` | 张三，4 份病历本的所有者 |
| `wangwu` | 王五，只有一份会议纪要 |

登录页不列演示账号，用上表的账号 + 上面的统一口令即可（从前那几个“一键填充”按钮已经拿掉了）。

每个账号都有一对 SM2 密钥：公钥在库里（上传时用它封块密钥），私钥用他自己的登录口令封好后才入库。所以想搞一张「口令与库都到手」的局面，得两样都拿到。

**默认没有预设文件** —— 传什么文件、切成几块、每块多大，都在「文件与块」页里自己选（可以按块大小，也可以直接填「我想切成 3 块」）。想灌回 5 个演示文件：`python scripts/start_all.py --reset --demo`。

文件列表中每一行的**操作点都摆在「操作」列**，不用去猜「点文件标识」：**详情**（块分布 / 验证 / 改块）、**入池**（把这份文件的证据攒进证据池；同一份再点一次是「刷新」——池子按**下标集合**去重，不会多出一张卡）、**试解密**（密码学那道门，点下去才看到后端真的拒了你）。已经在池子里的文件，标识后面会带一枚 **已入池** 标记。
上传卡里的 **问顾问** 会给出一张**候选切法表**（15 档 + 「部署默认」，并标出「最快 / 最细 / 默认」三档口径），点任意一行的「用这一档」才生效；**不点，「自动（后端默认）」就一直是部署默认值** —— 顾问只给建议，不会自己改上传参数。

**逐块指纹，以及「简略 / 详细」**：每一块的**公开分量**就是它的指纹（「承诺验证」比的正是"密文与分量对不对得上"）。
文件详情页多了一张「块明细」表，按块列出它 —— 十六进制 24 位，**鼠标停在上面看完整十六进制**（还有十进制前 24 位与位长）；
证据池的每张卡片可以「细看逐块指纹」展开成一张"下标 → 指纹"的表（单张卡片自己开合，不受全局开关影响）；
完整性验证的结果里也逐块列出，右侧还标出这个下标是"谁的第几块"。
控制要不要铺这些指纹的是 **简略 / 详细** 开关：它是一个**界面偏好**（与主题、表格密度一样存 localStorage，
「个人中心 → 界面偏好」里也能改），三页共用，默认「详细」。
详细模式下文件详情会多问后端要一份分量数据（`?elements=1`），所以切换那一下会重新加载一次 —— 这是故意的：
简略模式那次响应里**根本没有**这些字段，光靠前端 `v-if` 是变不出来的。

## 3. 手工启动

```powershell
# 一、算法与演示（不需要起服务）
python demo.py                               # 端到端演示 + 性能指标

# 二、后端（单进程模式：节点是同一进程里的对象）
python scripts/seed.py --reset --demo        # 建库 + 演示账号 + 演示文件
python -m uvicorn backend.main:app --port 8000   # 起后端（不加 --reload）

# 三、前端（另开一个终端；proxy 默认指向 8000，所以后端得在 8000）
cd frontend
npm install                                  # 只需一次
npm run dev                                  # http://127.0.0.1:5173
npm test                                     # 前端单元测试（Node 自带 node --test，零新依赖）

# 四、对跑着的后端做端到端冒烟（不经过前端，直接打接口）
python scripts/smoke.py --base http://127.0.0.1:8000

# 五、跨进程模式（真节点进程，各有各的 SQLite；默认 4 台，台数可改）
python scripts/run_nodes.py --fresh             # 终端 1（Ctrl+C 一起退）
# 终端 2：把打印出来的那行环境变量设上，再跑一样的命令
$env:VDS_NODE_URLS = "node-1=http://127.0.0.1:9101,node-2=http://127.0.0.1:9102,node-3=http://127.0.0.1:9103,node-4=http://127.0.0.1:9104"
python scripts/seed.py --reset --demo
python -m uvicorn backend.main:app --port 8000
```

> ⚠️ 手动跑的这一套**不读** `nodes/deploy.json`：“端口”那张卡片管的是**一键启动**那套
> （它会按配置拼 `VDS_NODE_URLS` 与 `--port`）。所以在界面上把端口改过之后，这几条命令
> 里的 `9101` / `8000` 也要跟着改成你设的那个；每台端口不一样的写法用
> `python scripts/run_nodes.py --urls "node-1=http://127.0.0.1:9201,..."`。

> ⚠️ 后端必须单进程单 worker：全局向量在内存里，多 worker 会各持一份并互相覆盖。注意这与「存储层拆进程」不矛盾：拆的是存数据的节点，协调者仍然只有一个。

**前端换后端端口**：设 `VDS_API_TARGET` 再启 dev server（如 `$env:VDS_API_TARGET='http://127.0.0.1:8099'`）。前端一律请求同源 `/api/...`，由 Vite 的 proxy 转给后端。
（一键启动会自动设好它 —— 见 `scripts/start_all.py` 的 `start_frontend`；所以**界面上改过后端端口**
之后，只要用 `一键启动.cmd` / 「立刻重启」，这个变量不需要你操心。）

**前端自己的端口**：默认 5173；`vite.config.js` 也认 `VDS_FRONTEND_PORT`，一键启动用 `--port` 显式传。

## 4. 两种运行模式

|  | 单进程（默认） | 跨进程（设了 `VDS_NODE_URLS`） |
|---|---|---|
| 节点是什么 | 同一进程里的 N 个 `NodeState` 对象 | N 个独立进程，各自一个 `node.db` |
| 协调者拿到什么 | 直接访问 `transport.states[nid]` | 只能 HTTP 说话（`HttpTransport`） |
| 节点状态 / 密文存哪 | 协调者库里 | 各节点自己的库里 |
| 代数结果 | 与跨进程逐位相同（有测试钉住） | 同上 |

切换只需要设 / 不设一个环境变量。**两种模式的库不能混用**：协调者启动时发现库里还留着单进程模式的节点状态，会直接拒绝启动（`--reset` 重来）。

**副本**：每块默认存 2 份，落在两台不同的机器上。删掉一台的数据目录，数据还在 —— 读取自动改问另一份副本。副本数由 `VDS_REPLICA_FACTOR` / `Settings.replica_factor` 定，上限是机器台数。

## 5. 后端接口一览

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | — | 登录，返回 JWT |
| GET | `/api/auth/me` | 登录 | 当前用户 + 公钥指纹 + 有没有密钥对 |
| POST | `/api/auth/logout` | 登录 | 丢掉内存里那把会话私钥 |
| GET | `/api/files` | 登录 | 所有文件（验证不受限）；每行标出「我能不能解密」 |
| POST | `/api/files` | 登录 | 上传 → SM4 → SM3 分量 → 承诺 → 用你的公钥封每块密钥 → 分发；`segment_bytes` 指定块大小，`nodes` 指定这次只往哪几台摊 |
| GET | `/api/files/{id}` | 登录 | 详情 + 块分布 + 版本号。加 `?elements=1` 会额外返回**每一块的公开分量**（十进制字符串），供界面「详细」模式显示逐块指纹（不带时响应不含该字段；1024 块的文件会因此多出几百 KB） |
| PATCH | `/api/files/{id}` | 只有所有者 | `op=modify`（改一块）/ `op=append`（追加）/ `op=truncate`（删末尾，带 `drop_blocks`）。管理员也不行 |
| POST | `/api/files/{id}/decrypt` | 只有所有者 | 解密，否则 403。管理员也不行 |
| POST | `/api/query` | 登录 | 按全局下标验证（不受限） |
| POST | `/api/query/files` | 登录 | 按文件一次查多个（可跨用户）→ 一份证据 |
| POST | `/api/query/verify-batch` | 登录 | 批量验证：一次验掉池子里的 m 份证据（不向节点取数据）。⚠ 比逐份验慢（实测 1.68×） |
| POST | `/api/evidence/disagg` | 登录 | 分解：从一份已有证据里拆出子集证据（不向节点取数据） |
| GET | `/api/registry/{i}` | 登录 | 全局下标 → 「谁的第几块、存在哪台」 |
| GET | `/api/status` | 登录 | 公开参数 + 全局摘要 δ |
| GET | `/api/nodes` | 登录 | 各台服务器现状（块分布） |
| POST | `/api/plan` | 登录 | 块大小顾问：给文件大小，按实测曲线建议怎么切（只读） |
| POST | `/api/por` | 登录 | 存储证明：不取内容，随机挑战后确认各节点还存着 |
| GET | `/api/nodes/pending` | 登录 | 有没有「写推失败、还没补」的更新 |
| POST | `/api/nodes/retry-push` | 管理员 | 补推：把上次没推成功的更新只补推给没跟上的那几台 |
| GET/POST/PATCH/DELETE | `/api/admin/users` | 管理员 | 增删改用户。建用户时顺带生成密钥对；改口令只能改自己的 |
| GET | `/api/admin/audit` | 管理员 | 审计流水（只记元数据）。可选 `target` / `actor` 精确匹配过滤 |
| POST | `/api/admin/check` | 管理员 | 跑一遍 `store.check()`。可能带 `notes`（**提示**，不是错误）：缩容后、重启前，被摘掉的机器还留着旧副本 |
| GET | `/api/admin/deploy` | 管理员 | 服务器台数：现在跑着几台 / 配置里几台 / 要不要重启 |
| GET | `/api/admin/ports` | 管理员 | 端口：配置里那一套（后端 / 前端 / 每台节点）+ 现在跑着的那一套 + 要不要重启 |
| POST | `/api/admin/ports/plan` | 管理员 | **只探不写**：每个端口空不空（真去 bind 一下），以及“自己撞自己”的清单 |
| PUT | `/api/admin/ports` | 管理员 | 保存端口（重启后生效）。**填重了 409 拦下；被别的程序占着只提示、照样保存** |
| GET | `/api/admin/deploy/plan` | 管理员 | **只算不动**：改成 N 台会怎样（要摘掉哪几台、要搬多少块、有没有搬不动的） |
| PUT | `/api/admin/deploy` | 管理员 | 保存台数（重启后生效）。**台数变小时先搬块、再写配置** |
| POST | `/api/admin/deploy/restart` | 管理员 | 一键重启：拉起一个独立窗口，停掉节点/后端/前端再按新台数起 |
| POST | `/api/admin/deploy/redistribute` | 管理员 | 手工把不足的副本补齐（不改台数） |
| GET | `/api/perf/summary` | 登录 | 运行期性能指标：各操作的耗时与阶段样本（采集在 `backend/metrics.py`），性能页用它画实时图 |

## 6. 测试与验证

> ⚠️ **本副本的 `tests/` 与 `tests_core/` 目录已被移除**（`pyproject.toml` 中有注明，完整测试在另一份副本 `mima/vds-system` 中）。因此下面的 `pytest` 命令在本副本不会跑出 829 条 —— 需在保留测试的那份副本里执行。


## 7. 关键实测数字

> 配置：`|N| = 1024`、`l = 256`（每段密文 1 KB，摘要 32 字节）、`n_max = 8192`（当前默认）、4 台服务器。数字来自本机实测，不同机器会差，`scripts/bench_batch.py` 可重跑。

### 7.1 性能指标

| \|Q\|（查询块数） | 凭证数 | 服务器 | 证明生成 | 聚合 | 验证 | 证据字节 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1 | 1 | 12.2 ms | 0.0 ms | 4.0 ms | 256 |
| 2 | 2 | 2 | 24.5 ms | 14.3 ms | 8.4 ms | 256 |
| 4 | 4 | 4 | 42.9 ms | 65.3 ms | 16.9 ms | 256 |
| 8 | 4 | 4 | 27.6 ms | 176.8 ms | 38.2 ms | 256 |
| 14 | 4 | 4 | 0.1 ms | 261.6 ms | 56.6 ms | 129 |

**证据规模恒为两个群元素（上界 2 × 128 = 256 字节）**，与查询块数、向量长度都无关 —— 这是 succinct 的硬指标。|Q|=14 那行 129 字节，是因为此时 `I` 覆盖全部位置，空乘积使 `Λ_I = 1`，只剩一个群元素。

其余：单个文件上传 130~1300 ms（随全局块数增长）、SM4 加密 1 MB ≈ 20 ms、全面自检 184 ms。

### 7.2 批量验证（规划里写「不做」，先量再定）

`|N| = 1024, l = 256, n = 64 块 / 8 个文件`：

| 做法 | 耗时 | 说明 |
|---|---:|---|
| 一次查全部 64 块（一份证据） | 2097.7 ms | 设计 B 的主路径，跨文件天然合成一份 |
| 逐块各查一次（64 份单块证据） | 5022.0 ms | 比合一份慢 2.4 倍 |
| 逐份 `svc.verify`（64 份已有证据） | 318.4 ms | 主路径上「验证」那一栏 |
| 验证一份覆盖 64 块的证据 | 331.0 ms | 与上一条同量级 —— 代价看块数，不看份数 |
| 批量方程（两条信道都合，随机系数） | 684.7 ms | 慢 2.15 倍 |

**为什么批量反而更慢**：本项目 `svc.verify` 已把论文的 O(ℓ|I|²) 换成 `add_back` 链的 O(ℓ|I|) 次小指数模幂；批量法必须回到「少次、但每次指数有 |I|(ℓ+1) 位」的形式，模幂次数差不多、指数却大一个数量级，于是净亏。**而「跨文件」那一半收益早就拿到了**（表里第一行 vs 第二行差 2.4 倍），这才是真正想要的东西。

### 7.3 与 `l = 128` 档的对照

| 项 | \|N\|=1024, l=128 | \|N\|=1024, l=256（本档） |
|---|---|---|
| commit | 10.5 ms/块 | ~19 ms/块（≈×1.8） |
| 验证 | 2.2 ms/块 | ~4 ms/块 |
| 文件上限（n_max=8192） | 128 KB | 8 MB |

> ⚠️ **文件大小其实由「块数上限」（`n_max`）决定，不是字节数。** 刚 `--reset --demo` 建好的演示库已用掉 12 个位置 ⇒ 8 MB（1 KB 块 → 8192 块）会被 400 拒；要传大文件得先把块调大（如 4 KB 块 → 32 MB）或清库。请求里的下标列表上限 `backend/schemas.py::MAX_INDICES = 8192` 必须 ≥ `n_max`。
>
> ⚠️ **秒表与估算会差很多，不是 bug**：界面上传卡的「预计耗时约」用的是 19 ms/块（只算逐块承诺），不含每块的密钥封装与全网推送。实测 200 块全流程 ≈61 s，而同一次的估算只有 3.8 s，差 16 倍。界面上已注明系数口径。
